FRAUD SMS / WHATSAPP REFERENCE DATASET
======================================

Purpose:
Use this file as a local reference dataset for the Screenshot Analyzer / Fraud Message Checker.
The checker should compare OCR-extracted text and detected elements against these known fraud patterns.
A match should increase the fraud score; it should NOT rely only on exact wording.

IMPORTANT:
- Treat these as known/example scam patterns.
- Do not require an exact text match.
- Compare meaning, intent, entities, urgency, requested action, links, phone numbers, attachments, and scam category.
- A similar message should be flagged as suspicious/high risk even if the wording is different.
- Do not classify a legitimate message as fraud only because it contains a bank name, OTP, URL, phone number, or urgency.

==================================================
MATCHING LOGIC FOR THE WEBSITE
==================================================

DO NOT implement:
if exact_text == dataset_text:
    fraud = true

Instead use semantic, contextual, and intent-based matching:

Suggested scoring approach:
+30  High-severity attack matching (APK payload, digital arrest, utility cutoff)
+25  Known scam category/intent similarity
+20  Suspicious domain / lookalike link / shortened URL
+20  Malicious file attachment (APK, EXE)
+15  Account blocking / security / legal intimidation threat
+15  Urgency / countdown pressure
+15  Direct phone callback bait (vishing)
+10  Unexpected payment / fee demand
+10  Sensitive credential / PII request
+10  Brand / Government / Utility impersonation
+10  Unknown sender + unsolicited social engineering context

Cap score at 100.

Score Interpretation:
0–20   LOW RISK (Standard informational / genuine OTPs / receipts)
21–40  CAUTION (Unverified unsolicited outreach)
41–60  SUSPICIOUS (Multiple red flags requiring manual verification)
61–80  HIGH RISK (Strong likelihood of fraud / phishing)
81–100 CRITICAL FRAUD (Severe confirmed fraud pattern / malware / vishing / extortion)


==================================================
FALSE-POSITIVE PROTECTION SAFEGUARDS
==================================================

Never declare fraud solely because:
- A bank name appears
- An OTP code appears
- A link or phone number appears
- An order receipt or delivery notification appears
- The sender is unknown
- The message contains polite or urgent language

Safe examples to protect:
- Genuine login OTP with "Never share OTP with anyone" and no link.
- Genuine bank account credit/debit transaction SMS with available balance.
- Genuine store receipt or order delivery notification from verified domains.
