FRAUD SMS / WHATSAPP REFERENCE DATASET
======================================

Purpose:
Use this file as a local reference dataset for the Screenshot Analyzer / Fraud Message Checker.
The checker should compare OCR-extracted text and detected elements against these known fraud patterns.
A match should increase the fraud score; it should NOT rely only on exact wording.

IMPORTANT:
- Treat these as known/example scam patterns.
- Do not require an exact text match.
- Compare meaning, intent, entities, urgency, requested action, links, phone numbers, attachments, and scam category.
- A similar message should be flagged as suspicious/high risk even if the wording is different.
- Do not classify a legitimate message as fraud only because it contains a bank name, OTP, URL, phone number, or urgency.

==================================================
EXAMPLE 1 — BANK / REKYC / APK PHISHING
==================================================

Original visible message:
"*URGENTLY REQUIRED:-Your Bank of Maharashtra ReKYC pending for Bank of Maharashtra CustID XXXX.Complete ReKYC Last Date 13.may 2025 to avoid A/c blocking. Open PDF file. Immediately Thank you!"

Attachment visible:
"Bank of Maharashtra A1..."
"18 MB · APK"

Known signals:
- Claimed organization: Bank of Maharashtra
- ReKYC / KYC request
- Account blocking threat
- Urgent action
- Deadline pressure
- Attachment
- APK file
- User instructed to open the file
- Banking identity impersonation

Scam category:
BANK_KYC_PHISHING
MALICIOUS_ATTACHMENT
BANK_IMPERSONATION

Risk:
CRITICAL / HIGH

Strong matching concepts:
"ReKYC pending"
"complete KYC"
"account will be blocked"
"avoid account blocking"
"last date"
"urgently required"
"open attached file"
"bank APK"
"banking APK"
"KYC APK"
"18 MB APK"
"customer ID"
"account suspension"

Recommended verdict:
LIKELY FRAUD / PHISHING

Recommended explanation:
The message claims to be from a bank, creates urgency by threatening account blocking, and asks the user to open an APK/attachment for KYC. This combination is a major phishing/malicious-attachment red flag.

==================================================
MATCHING LOGIC FOR THE WEBSITE
==================================================

DO NOT implement:

if exact_text == dataset_text:
    fraud = true

Instead use semantic/pattern matching.

Suggested scoring approach:

+25  Exact/near-exact known scam pattern
+20  Same scam intent/category
+15  Suspicious link or URL pattern
+20  Sensitive attachment such as APK
+15  Account-blocking/security threat
+10  Urgency pressure
+10  Unexpected payment request
+10  Sensitive information request
+10  Brand impersonation indicators
+10  Unknown sender + suspicious context
+10  Unsolicited job/prize/financial offer

Cap score at 100.

Suggested interpretation:

0–20   LOW RISK
21–40  CAUTION
41–60  SUSPICIOUS
61–80  HIGH RISK
81–100 CRITICAL

IMPORTANT:
Do not add points simply because a normal word appears.
Use context.

Example:
"OTP" alone = NOT fraud.
"Your OTP is 123456. Never share it." = potentially legitimate.
"Your OTP is 123456. Call this unknown number and tell us the OTP." = HIGH RISK.

"Amazon" alone = NOT fraud.
"Amazon: your code is..." with a genuine official domain may be legitimate.
"Amazon: your account is locked, click an unfamiliar domain to verify" = HIGH RISK.

OUTPUT FORMAT
==================================================

The checker should return:

VERDICT:
Likely Fraud / Suspicious / Likely Legitimate

RISK SCORE:
0–100

MESSAGE MEANING:
Explain in simple language what the message is trying to make the user do.

SCAM TYPE:
Example: Bank KYC Phishing

WHY:
List the exact evidence detected in the screenshot.

DETECTED ELEMENTS:
Sender
Phone number
URL
Attachment
Organization
Amount
Date
Requested action

RECOMMENDATION:
Tell the user what NOT to do and how to verify safely.

==================================================
FALSE-POSITIVE PROTECTION
==================================================

Never declare fraud only because:
- A bank name appears
- An OTP appears
- A link appears
- A phone number appears
- A delivery message appears
- The sender is unknown
- The message uses urgent language

Combine multiple signals and message intent.

If evidence is insufficient:
VERDICT = SUSPICIOUS
not
VERDICT = CONFIRMED FRAUD
