## Confirmed defect and bounded fix

A synthetic Canvas whose asynchronous `toBlob` callback succeeded but whose subsequent `toDataURL` call threw reproduced an uncaught callback exception while `renderRedactedImage` stayed pending. The existing download handlers also lacked error recovery. This is an injected error-path reproduction, not evidence that the earlier production download timeout had this cause.

The renderer now awaits the Blob and encodes its data URL in the async function, so encoding exceptions reject normally. All three redaction surfaces (homepage modal, tool-layout modal and standalone workspace) use one guarded export binding: visible non-sensitive retry feedback, no original-image fallback, button re-enabled after failure, one export at a time, and no obsolete download after image/mask change or editor dismissal. Existing modal closes only after a download request is issued. The wording says “Download requested”; a click cannot confirm the browser saved a file. The request uses an attached anchor and releases the object URL after a grace interval rather than immediately.

Independent review also reproduced an existing privacy-sensitive host-state problem: a new scan cleared mask boxes while leaving the previous image and masked preview in an open modal, allowing an unmasked old-image export. Both modal hosts now close and invalidate the old image immediately when a new scan/reset starts. Analysis-generation guards ignore stale reads/results/errors; modal-opening guards prevent delayed decode from reopening after dismissal or replacement. Preview snapshots are captured before asynchronous imports so invalidation cannot repaint stale output.

No redaction algorithms, OCR, scoring, tracking configuration, dependencies, runtime pins or lockfile changed. Preview redraw error handling is outside this export-only change.

## Real local pixel/PNG checks

`scripts/verify-redaction-export.mjs` calls the real application renderer with `@napi-rs/canvas` 1.0.9 (Skia) installed in an isolated temporary prefix, outside the project dependencies. This is a local Canvas adapter, not a browser replacement or a production-download test.

The authored 64×48 fixture includes varied colors, transparent pixels and a known synthetic PNG Comment (`tEXt`) marker. Pixel assertions check all 3,072 pixels: 492 blackout/whiteout pixels are fully opaque and exact; the other 2,580 equal an unmasked renderer baseline. Fractional coordinates and image-edge clipping are covered. Invalid empty/outside boxes are ignored as before. The output dimensions/type are preserved, the tested Comment marker and `tEXt` chunk are absent, and Blob bytes match the data URL. Source/output PNGs and the machine-readable result are in `audit/export-qa/`.

Exported PNG still has encoder-created `sBIT` and `sRGB` chunks. “No copied source Comment” does not mean every kind of metadata is absent. JPEG/WebP/EXIF/C2PA and other source metadata formats were not exercised. Blur/pixelation readability is not certified; opaque masks remain recommended.

Reproduce with the pinned runtime, after installing the optional Canvas QA tool into a separate temporary prefix:

```sh
SC_CANVAS_MODULE=/absolute/path/to/isolated/node_modules/@napi-rs/canvas/index.js \
node --import tsx scripts/verify-redaction-export.mjs
```
